# イントロクイズ 早押しシステム 実装指示書（改訂版）

## 0. 前提と制約

研究会の交流会（本日夜）で使う、10分間の出し物用システム。参加者はスマホでQRを読み、名前を入れて早押しボタンを押す。投影画面が回答者名を表示し、曲を止める。

**この制約を最優先で守ること。**

- **単一プロセス前提。** 早押しの排他制御をプロセスメモリ上のフラグで行うため、複数インスタンスにスケールさせてはいけない。Redis等の外部ストアは使わない。
- **永続化なし。** DBを導入しない。全状態はメモリ上。プロセス再起動で全部消えてよい。
- **認証なし。** 名前は自己申告。不正対策は行わない。
- **音源ファイル（mp3等）は存在しない。** 再生は YouTube 経由か、システム外の手動再生で行う。下記6を参照。
- **本日中に動くことが最優先。** 迷ったら機能を削る。「10. スコープ外」を厳守すること。

## 1. 技術スタック

| 領域 | 採用 |
|---|---|
| フロント | Vite + React 18 + TypeScript + Tailwind CSS |
| サーバー | Node.js + TypeScript（`tsx` で直接実行、トランスパイル工程を作らない） |
| 通信 | Socket.IO（`ws` を直接使わない。再接続処理を自前で書かないため） |
| HTTP | Express（Viteビルド成果物の静的配信 + QR生成） |
| QR | `qrcode` パッケージでサーバーサイド生成 |
| 再生 | YouTube IFrame Player API（`<script src="https://www.youtube.com/iframe_api">` を動的挿入。npmパッケージは使わない） |
| 効果音 | Web Audio API の `OscillatorNode` で生成。**音声ファイルを一切用意しない** |

依存パッケージはこれで足りる。追加しないこと。

```
express socket.io qrcode
vite @vitejs/plugin-react react react-dom typescript tsx tailwindcss
```

YouTube IFrame API の型は `@types/youtube` を入れてもよい。面倒なら `declare global { interface Window { YT: any; onYouTubeIframeAPIReady: () => void } }` で済ませてよい。

## 4. 通信仕様

### 4.1 共有型（`src/types.ts`）

```ts
export type Player = { id: string; name: string };

export type State = {
  buzzedBy: Player | null;   // 現在ボタンを押している人。nullなら受付中
  lockedIds: string[];       // このラウンドで誤答した socket.id
  players: Player[];         // 参加者一覧
};
```

### 4.2 クライアント → サーバー

| イベント | 引数 | 発火元 | 動作 |
|---|---|---|---|
| `join` | `(name: string, ack)` | 参加者 | 名前を登録。`ack({ ok: true, id, name })` を返す。名前は trim して12文字で切り、空なら「名無し」 |
| `buzz` | なし | 参加者 | 早押し。下記4.4の条件を満たす場合のみ受理 |
| `host:reset` | なし | 投影画面 | 押下を取り消す（ロックはしない） |
| `host:wrong` | なし | 投影画面 | 誤答。押した人を `lockedIds` に追加し、受付を再開 |
| `host:nextRound` | なし | 投影画面 | 次の曲へ。`buzzedBy` と `lockedIds` を両方クリア |

### 4.3 サーバー → クライアント

| イベント | 引数 | 用途 |
|---|---|---|
| `state` | `State` | 状態が変わるたびに全クライアントへ同報。**接続直後にも必ず1回送る** |
| `buzzed` | `Player` | 押された瞬間の単発通知。投影画面はこれを受けて再生停止とビープを行う |

`state` に全情報が載っているので、クライアントは基本的に `state` を描画するだけでよい。`buzzed` は「音を止める」「ビープを鳴らす」という副作用のためだけに存在する。

### 4.4 早押しの排他制御

サーバー側の `buzz` ハンドラは以下の順に判定し、いずれかに該当したら**黙って return する**（エラーを返さない）。

1. `buzzedBy !== null` → 既に誰かが押している
2. `lockedIds.includes(socket.id)` → このラウンドで誤答済み
3. 未 `join` → 参加登録がない

すべて通過したら `buzzedBy` をセットし、`buzzed` と `state` を同報する。

Node.js はシングルスレッドなので、この判定と代入の間に他のリクエストが割り込むことはない。ロック機構を追加しないこと。

### 4.5 再接続時の復帰

**接続を状態の唯一の情報源にしないこと。** モバイルブラウザはバックグラウンドに回ると接続を切るため、以下を必ず実装する。

- サーバーは `connection` 時に、まだ `join` していない相手にも `state` を送る
- 参加者クライアントは `localStorage` に名前を保存し、`socket.on("connect")` のたびに `join` を送り直す（サーバーはメモリ管理なので `socket.id` が変わると登録が消えている）
- `disconnect` 時、サーバーは該当プレイヤーを `players` と `lockedIds` から削除し、その人が `buzzedBy` だった場合は `null` に戻す

## 5. 各画面の要件

### 5.1 参加者画面（`/`）

2ステート。名前入力 → 早押しボタン。

**名前入力**: テキスト入力1つと送信ボタン1つ。Enterでも送信できること。`localStorage` に前回の名前があれば初期値に入れる。

**早押しボタン**: 画面の縦幅いっぱいを占める大きなボタン。以下の4状態を、色と文言で明確に区別する。

| 状態 | 表示 |
|---|---|
| 受付中 | 押せる。赤系 |
| 自分が押した | 押せない。緑系。「あなた！」 |
| 他人が押した | 押せない。灰色。「◯◯さんが押しました」 |
| 自分がお手つき済み | 押せない。灰色。「この曲はここまで」 |

**タップ時はサーバーの返事を待たず、即座にボタンを `disabled` にすること。** 往復を待つと必ず連打される。あわせて `navigator.vibrate(30)` を呼ぶ（対応端末のみ効く）。

`<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no">` を入れ、`-webkit-tap-highlight-color: transparent` を当てる。ダブルタップズームで誤操作されるのを防ぐ。

接続状態（接続中／再接続中）を小さく常時表示する。当日トラブったときの切り分けが早くなる。

### 5.2 投影画面（`/screen`）

プロジェクター投影用。**遠くの席から読めることを最優先**にレイアウトすること。回答者名は画面高の3分の1を使うくらいの大きさでよい。

構成は2カラム。

- **左（狭い）**: QRコード（`/qr.png` を `<img>` で表示）、接続URLのテキスト、参加者名の一覧
- **右（広い）**: 現在の問題番号、再生状態、回答者名、答え合わせ表示、YouTubeプレイヤー領域（下記6.3）

表示する内容は状態によって切り替える。

| 状態 | 右カラムの表示 |
|---|---|
| 再生前 | 「第N問」と大きく |
| 再生中 | 経過秒数。プレイヤーは目隠しカバーで覆う |
| 押された | 回答者名を最大サイズで。背景色を変える |
| 答え表示 | 曲名 / アーティスト / 誰の推し曲か。カバーを外して映像を見せる |

現在の再生モード（YouTube / 手動）を隅に小さく常時表示すること。

### 5.3 キーボード操作（投影画面のみ）

| キー | 動作 |
|---|---|
| `Space` | 再生 / 一時停止 |
| `1` | 正解 → 答えを表示（カバーを外す） |
| `2` | 誤答 → `host:wrong` を送り、続きから再生再開 |
| `R` | 押下を取り消す（`host:reset`）。誤検知の救済用 |
| `N` | 次の曲へ（`host:nextRound`）。答え表示を消し、頭出し |
| `←` `→` | 曲を手動で選択 |
| `M` | **再生モードの切り替え**（YouTube ↔ 手動。下記6.1） |

`Space` はブラウザのデフォルト動作（スクロール）が入るので `preventDefault()` すること。

画面下部にキー割り当ての一覧を小さく常時表示しておく。当日操作を間違えないための保険。

## 6. 再生（今回の改訂の中心）

### 6.1 2つのモード

**両方を実装し、`M` キーでいつでも切り替えられるようにすること。** 当日 YouTube 側で何か起きたときに、システムを落とさず手動に逃げられるようにするため。

| モード | 内容 |
|---|---|
| `youtube`（既定） | YouTube IFrame Player API で再生・停止をアプリが制御する |
| `manual` | アプリは再生に一切関与しない。操作者が YouTube Music アプリ等で手動再生し、押下時に手で止める |

`manual` モードでは `Space` と再生位置に関する処理をすべて無効化し、画面には曲順と答えだけを出す。**早押し・ビープ・名前表示・答え表示は両モードで完全に同一に動くこと。**

### 6.2 ビープ音（両モード必須）

`buzzed` を受信した瞬間、投影画面で短いビープを鳴らす。Web Audio API で生成し、音声ファイルは使わない。

```ts
// 880Hz を 0.12 秒。矩形波でよく通る音になる
const osc = ctx.createOscillator();
const gain = ctx.createGain();
osc.type = "square";
osc.frequency.value = 880;
gain.gain.setValueAtTime(0.2, ctx.currentTime);
gain.gain.exponentialRampToValueAtTime(0.001, ctx.currentTime + 0.12);
osc.connect(gain).connect(ctx.destination);
osc.start();
osc.stop(ctx.currentTime + 0.13);
```

`AudioContext` はモジュールスコープで1つだけ作って使い回すこと。毎回 `new` するとブラウザが詰まる。

**手動モードではこのビープが唯一の停止トリガーになる。** 操作者はこれを聞いて手で止めるので、確実に鳴ること、かつ曲より大きく聞こえることを優先する。

### 6.3 YouTube プレイヤーの実装

**問題数ぶんの `<div>` を用意し、それぞれに `YT.Player` を1つずつ作る。** 曲を切り替えるたびに `loadVideoById` で差し替える実装にしないこと。プレイヤー生成と初回バッファに数秒かかり、イントロの頭が欠ける。

初期化時に全プレイヤーを作り、それぞれ `cueVideoById({ videoId, startSeconds })` で待機させる。表示は現在の1曲ぶんだけにし、他は画面外に置く（`display: none` にはしない。6.4を参照）。

主要な制御はこれだけ。

| 操作 | 呼び出し |
|---|---|
| 再生 | `player.playVideo()` |
| 停止 | `player.pauseVideo()` |
| 頭出し | `player.seekTo(startSec, true)` |
| 準備完了判定 | `onReady` イベント |

`onError` は必ずハンドリングし、画面に曲番号とエラーコードを出すこと。当日の切り分けが一瞬で終わる。エラーコード101と150は埋め込み禁止動画を意味するので、その旨を日本語で表示すること。

`playerVars` は以下を指定する。

```ts
{ controls: 0, disablekb: 1, rel: 0, modestbranding: 1, playsinline: 1 }
```

### 6.4 目隠しカバー

イントロクイズなので、再生中に映像でネタバレしてはいけない。プレイヤーを絶対配置し、その上に不透明な `<div>` を重ねて覆う。

**プレイヤー自体を `display: none` や 1x1 px にしないこと。** 再生が止まる、あるいは YouTube の埋め込み規約に触れる。カバーで覆う方式にし、正解表示（`1` キー）のタイミングでカバーを外して映像を見せる。ここが答え合わせの見せ場になる。

### 6.5 プリロードと自動再生解除

投影画面に「準備完了」ボタンを置く。クリック時に以下をまとめて行う。

1. `AudioContext` を `resume()` する
2. 全 YouTube プレイヤーの `onReady` が揃うまで待つ（`3 / 4 準備完了` と進捗表示）
3. 揃ったら本編に進む

ブラウザは操作なしに音を出せないので、この1クリックが必須。手動モードでも `AudioContext` の解除は必要なので、このボタンは両モードで出すこと。

### 6.6 問題データ（`public/songs.json`）

```json
[
  {
    "videoId": "dQw4w9WgXcQ",
    "title": "曲名",
    "artist": "アーティスト名",
    "owner": "この曲を挙げた人の名前",
    "startSec": 0
  }
]
```

`videoId` は YouTube URL の `v=` 以降。`startSec` はイントロ開始位置。

## 7. サーバー実装

### 7.1 静的配信

```ts
app.use(express.static(path.join(__dirname, "../dist")));
app.get("*", (_req, res) => res.sendFile(path.join(__dirname, "../dist/index.html")));
server.listen(process.env.PORT || 3000);
```

`process.env.PORT` を読むこと。ホスティング側が指定したポートで待たないと起動に失敗する。

### 7.2 QRエンドポイント

`GET /qr.png` で、接続先URLのQRをPNGで返す。URLは `process.env.PUBLIC_URL` があればそれを、なければ `req.headers.host` から組み立てる。

```ts
QRCode.toBuffer(url, { width: 600, margin: 2, errorCorrectionLevel: "M" })
```

### 7.3 開発時のプロキシ

`vite.config.ts` で `/socket.io` をサーバーにプロキシする。

```ts
server: {
  proxy: { "/socket.io": { target: "http://localhost:3000", ws: true } }
}
```

**Render の Web Service を使う。** GitHubリポジトリを連携する。

| 項目 | 値 |
|---|---|

音源ファイルを持たなくなったので、リポジトリは軽いままで済む。

## 9. 受け入れ条件

以下がすべて通ったら完成とする。

1. スマホでQRを読み、名前を入れて参加できる
2. スマホでボタンを押すと、投影画面でビープが鳴り、名前が大きく出る
3. 2台目以降のスマホは、1台目が押した後にボタンが押せなくなる
4. `2`（誤答）で受付が再開し、押した本人だけがロックされ、他の人は押せる
5. `1`（正解）で曲名・アーティスト・推した人が表示され、目隠しカバーが外れる
6. `N` で次の曲に進み、全員のロックが解除される
7. **スマホをホーム画面に戻してから再度開いても、名前を入れ直さずに復帰できる**
8. `M` で手動モードに切り替えても、1〜7（`Space` 関連を除く）がそのまま動く
9. YouTubeモードで `Space` を押すと再生され、押下時に `pauseVideo()` で止まる
10. 曲の切り替え時にプレイヤー生成の待ち時間が発生しない

## 11. 実装順序

上から順に作り、各段階で動作確認してから次に進むこと。途中で時間切れになっても使える状態を保つ。

1. サーバー（Socket.IO のイベント一式）と、`console.log` だけの最小クライアント
2. 参加者画面（名前入力 + ボタン + 4状態の描画）
3. 投影画面の**手動モード**（ビープ + 名前表示 + 曲送り + 答え表示）
4. キーボード操作
5. YouTube プレイヤー統合（モード切り替え、目隠しカバー）
6. QR表示、参加者一覧、見た目の調整

**3 まで動けば出し物として成立する。** 手動モードが先に完成していれば、5 が間に合わなくても当日は問題なく実施できる。**この順序を入れ替えないこと。**

## 12. 当日までに人間側でやること（実装対象外）

エージェントの作業ではないが、これが済んでいないとシステムが動かない。

1. **4曲ぶんの YouTube 動画IDを決める。** 公式チャンネルの音源を優先する。
2. **各動画の埋め込み可否を確認する。** ブラウザで `https://www.youtube.com/embed/(動画ID)` を直接開き、再生できれば埋め込み可。ここで弾かれる動画が必ず何本か出るので、代替を用意しておく。
3. **投影PCのChromeで YouTube にログインしておく。** Premium 契約が埋め込みプレイヤーにも効くかは保証がないので、テスト再生で広告が入らないか実際に確かめること。広告が入るようなら手動モードに切り替える。
4. **投影PCの音声出力先を確認する。** HDMI接続で出力がプロジェクター側に切り替わることがある。
