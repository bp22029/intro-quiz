# イントロクイズ早押しシステム

会場のプロジェクターとスマホだけで、イントロクイズの早押しを回すためのWebアプリです。参加者はアプリのインストールも会員登録も不要で、投影画面に出たQRコードを読むだけで参加できます。

研究会の交流会で10分間の出し物として実際に運用したものを、そのまま公開しています。

```
  参加者のスマホ            投影スクリーン              司会の手元PC
  ┌──────────┐            ┌──────────────┐          ┌──────────────┐
  │   早押し   │  ─────▶  │  QR / 回答者名 │  ◀────  │  進行を操作する │
  │   ボタン   │  buzz    │  正解発表      │   操作   │  正解 / お手つき │
  └──────────┘            └──────────────┘          └──────────────┘
        └────────────── Socket.IO サーバー（状態を1か所で持つ）──────────────┘
```

## 3つの画面

| パス | 誰が見るか | 役割 |
|---|---|---|
| `/` | 参加者 | スマホで名前を登録し、早押しボタンを押す |
| `/screen` | 会場全員 | プロジェクター投影用。QR・問題番号・回答者名・正解発表。**表示専用** |
| `/host` | 司会・出題者 | 手元PCで進行を操作する。ここだけが状態を変えられる |

## 出題者から見てできること

**早押し**

- 最初に押した1人だけが受理される。判定はサーバー側の単一プロセスで行うので、同時押しでも二重に通らない
- 押した瞬間、投影画面と管理画面の両方でビープが鳴り、回答者名が大きく出る
- 「押し直し」でロックせずに受付へ戻せる（誤検知・押し間違いの救済）

**お手つき**

- 「× お手つき」を押すと、その参加者はその問題だけロックされ、全画面に `3 → 2 → 1 → GO!` のカウントダウンが出て受付が再開する
- ロックは端末に保存した `clientId` と表示名の両方で照合する。**スマホをリロードしても、名前を変えても、別ブラウザで入り直しても解除されない**
- 管理画面の参加者名をクリックすれば、司会の判断で個別に付け外しできる

**正解発表**

- 「正解は…」の溜めを入れてから、曲名を1文字ずつ浮かび上がらせる。溜めの秒数は管理画面から調整できる
- 曲名・アーティストに加えて「◯◯さんの推し曲」を出せる。持ち寄り形式の出し物向け

**出題データ**

- 曲リストは管理画面から直接編集できる。編集結果は「JSONとしてコピー」で `songs.json` に貼り戻せる
- YouTubeのURLを貼れば、動画IDと `t=` の再生開始位置を自動で取り込む

**答えが漏れない**

- 曲名・アーティスト・推した人は、投影画面と管理画面にしか配信していない。参加者の端末には空で配られる
- 通信を覗いても答えが分からないことは、`scripts/leaktest.mjs` で検証している

## 動かす

Node.js 20以降が必要です。

```bash
git clone https://github.com/<あなた>/intro-quiz.git
cd intro-quiz
npm install
cp public/songs.sample.json public/songs.json   # 曲データを用意する
```

開発時は、ターミナルを2枚開いて両方をリポジトリのルートで実行します。

```bash
npm run server   # Socket.IO・HTTPサーバー（ポート3000）
npm run dev      # Vite開発サーバー（通常はポート5173）
```

- 参加者: `http://localhost:5173/`
- 投影画面: `http://localhost:5173/screen`
- 管理画面: `http://localhost:5173/host`

スマホ実機から試すときは、PCとスマホを同じLANに繋ぎ、Viteが表示する Network URL（例 `http://192.168.1.20:5173/`）を開きます。

本番相当で確認する場合はビルドしてから単一のサーバーで配信します。

```bash
npm run build
npm start        # http://localhost:3000 で3画面すべてを配信
```

`npm run typecheck` で型チェックのみ実行できます。

## 曲データを用意する

`public/songs.sample.json` をコピーして `public/songs.json` を作ります。**`public/songs.json` は `.gitignore` 済みです**（参加者の実名が入るため、コミットされない運用にしています）。

```json
[
  {
    "videoId": "dQw4w9WgXcQ",
    "title": "曲名",
    "artist": "アーティスト名",
    "owner": "曲を推した人の名前",
    "startSec": 0,
    "chorusSec": 43
  }
]
```

| 項目 | 内容 |
|---|---|
| `videoId` | YouTube URLの `v=` より後ろにある動画ID |
| `title` | 答えとして投影する曲名 |
| `artist` | 答えとして投影するアーティスト名 |
| `owner` | 曲を推した人の名前。画面に「さんの推し曲」が付く。不要なら空文字 |
| `startSec` | イントロ再生を開始する位置（秒） |
| `chorusSec` | 正解時にジャンプして再生するサビの位置（秒） |

`songs.json` が無い場合は `songs.sample.json` にフォールバックするので、クローン直後でも起動はします。

## 再生モード

管理画面の右上で切り替えます。**既定は「手動」**です。

### 手動モード（既定）

曲の再生を、司会が別ウィンドウのYouTubeで行うモードです。管理画面の「▶ イントロ」「♪ サビ」ボタンが、`t=` 付きURLで**同じ名前の再生タブを使い回して**頭出しします。2回目以降はタブが切り替わらず、管理画面からフォーカスが外れません。正解を押したときにサビを自動で鳴らすこともできます（待ち時間は秒単位で調整可能）。

**問題を移ると、再生タブは自動で無音になります。** 正解発表で流したサビを手で止める必要はありません。別オリジンのタブは中身を触れませんが `location` への書き込みだけは許されているので、`about:blank` へ飛ばすことで音を止めています。タブ自体は閉じないので、次の曲でもフォーカスを奪わずに使い回せます。

早押しでの停止だけは手で行います。停止自体は同じ手が使えますが、再開に動画の読み込み直しが要るため、現状は入れていません。ビープが停止の合図になります。

### YouTubeモード

投影画面に埋め込んだYouTube IFrame Playerが曲を鳴らします（映像は非表示）。「▶ イントロ再生」「⏸ 一時停止」で操作でき、**早押しで自動停止**、**正解で `chorusSec` へ自動ジャンプ**します。全曲のプレイヤーが準備できたかは管理画面に「N / M 準備完了」で出ます。

### なぜ手動が既定なのか

YouTube埋め込みは、動画ごとに埋め込み再生が禁止されている（エラー101 / 150）、広告が入る、回線状況でイントロの頭が欠ける、といった当日に対処できない失敗をします。手動モードはそのすべてを人力で回避でき、早押し・ビープ・回答者表示・正解演出は手動モードでも完全に動きます。**本番前に全曲をYouTubeモードで通しで試して、1曲でも不安があれば手動で通す**という判断ができるように、2モードを用意しています。

なお、IFrame Playerを非表示にして音声だけ使う運用はYouTubeの利用規約上グレーです。継続的に使うなら手動モード、または自前の音源を検討してください。

## 設計の考え方

10分間の出し物を確実に成立させることを最優先に、意図的に機能を削っています。

**状態はサーバープロセスのメモリだけに持つ。** DBもRedisも使いません。再起動すれば参加者も進行状態も消えますが、10分の出し物ではその方が壊れる箇所が少なくなります。逆に、**早押しの排他制御が単一プロセス前提なので、本番サーバーを複数インスタンスに増やすと破綻します**。

**認証を持たない。** 参加者がログインする体験は、10分の出し物では成立しません。`/host` にも認証がないので、**公開URLで運用する場合は当日以外はデプロイを落としてください**。

**音声ファイルを1つも持たない。** 早押しやカウントダウンのビープは、すべて Web Audio の `OscillatorNode` で生成しています（[src/beep.ts](src/beep.ts)）。mp3を置かないので、リポジトリが軽く、読み込み失敗で音が鳴らない事故も起きません。ブラウザの自動再生制限に対しては、`/screen` の「投影を開始する」と `/host` の「操作をはじめる」の1クリックで解除する形にしています。

**参加者の識別は `localStorage` の `clientId`。** スマホがリロードしても、電波が切れて繋ぎ直しても、同じ人として復帰します。お手つきロックが「リロードで消える」のは出し物として致命的なので、ここだけは丁寧に作っています。

**投影画面は完全に表示専用。** `/screen` はサーバーの状態をそのまま描くだけで、キー操作も受け付けません。操作口を `/host` の1か所に絞ることで、当日「どっちの画面で操作するんだっけ」が起きないようにしています。

## 既知の制約

- 早押しの排他は単一プロセス前提。水平スケールできない
- サーバー再起動で参加者・進行状態がリセットされる
- `/host` に認証がない
- 手動モードでは、早押しでの停止だけは人の手で行う必要がある（問題を移ったときの停止は自動）
- YouTubeモードは、動画側の埋め込み設定・広告・回線に依存する

## 検証スクリプト

`scripts/` に、実際にSocket.IOで繋いで振る舞いを検証するスクリプトを置いています。引数を省略すると `http://localhost:3000` に接続します。

| スクリプト | 検証内容 |
|---|---|
| `buzztest.mjs` | 同時押しで1人だけ受理、お手つきロック、3秒後の受付再開、押し直し、未登録の拒否 |
| `hosttest.mjs` | 管理画面の操作が投影状態へ反映されるか、後から繋いだ画面への状態同期 |
| `relocktest.mjs` | 切断・再接続・名前変更をしてもお手つきが解除されないこと |
| `leaktest.mjs` | 参加者に答え（曲名・アーティスト・推した人）が配信されていないこと |
| `cleartest.mjs` | 「参加者を全員クリア」で、離脱者だけが消えて接続中の人は戻ること |
| `songstest.mjs` | 管理画面からの曲リスト編集が各画面へ配られること |
| `urltest.mjs` | YouTube URLからの動画ID・開始秒の抽出（サーバー不要） |
| `loadtest.mjs` | 同時接続を増やしたときの早押し応答時間の計測 |

```bash
npm start                              # 別ターミナルでサーバーを起動しておく
node scripts/buzztest.mjs
node scripts/loadtest.mjs http://localhost:3000 30
```

リモート環境に対して実行する場合は第1引数にURLを渡します。環境変数 `D` で各確認の待ち時間をミリ秒指定できます（遅い環境向け）。

```bash
D=1500 node scripts/hosttest.mjs https://<デプロイ先のホスト>
```

**これらのスクリプトは参加者の追加・問題選択・モード変更を実際に行います。本番進行中のサーバーには実行しないでください。**

## 技術構成

React + TypeScript + Tailwind CSS（Vite） / Express + Socket.IO（tsx で直接実行）。ビルド済みフロントエンドは同じExpressサーバーから配信するので、本番は1プロセスで動きます。型定義 [src/types.ts](src/types.ts) はサーバーとクライアントで共有しています。

## ライセンスと注意

- 曲データ（`public/songs.json`）はリポジトリに含みません。楽曲の再生は各自の責任と権利範囲で行ってください
- YouTube IFrame Player の利用は YouTube の利用規約に従ってください
- `owner` に実名を入れる場合、公開リポジトリにコミットしないよう注意してください
