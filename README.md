# イントロクイズ早押しシステム

会場のプロジェクターとスマホだけで、イントロクイズの早押しを回すためのWebアプリです。参加者はアプリのインストールも会員登録も不要で、投影画面に出たQRコードを読むだけで参加できます。

研究会の交流会で10分間の出し物として実際に運用したものを、そのまま公開しています。**複数の主催者が同時に、それぞれ別のクイズを開けます**（後述の「部屋」）。

## 触ってみる

**https://intro-quiz-u3vn.onrender.com**

登録もインストールも要りません。開いて「新しい部屋を作る」を押せば、その場で1問目まで進みます。

1. 上のURLを開いて **「新しい部屋を作る」** → 管理画面が出ます
2. **「投影画面を開く」** → プロジェクターに映す画面が別窓で開きます
3. その画面のQRをスマホで読むか、**「参加URLをコピー」** で出たURLを別のブラウザで開きます
4. 管理画面の **「▶ イントロ再生」** → スマホで **「押す！」** → **「○ 正解・答えを出す」**

デモ用に3曲（BUMP OF CHICKEN / ONE OK ROCK / ASIAN KUNG-FU GENERATION）が入っています。曲は管理画面の「曲を編集」からYouTubeのURLを貼って差し替えられます。

> **無料プランなので、しばらく使われていないと最初の表示に30秒〜1分かかります。** 白い画面のまま待つか、一度再読み込みしてください。
> 部屋はサーバーのメモリにしかありません。**誰も繋いでいない状態が2時間続くと消えます。** 本番で使うなら、出番の直前に部屋を作ってください。

```
  参加者のスマホ            投影スクリーン              司会の手元PC
  ┌──────────┐            ┌──────────────┐          ┌──────────────┐
  │   早押し   │  ─────▶  │  QR / 回答者名 │  ◀────  │  進行を操作する │
  │   ボタン   │  buzz    │  正解発表      │   操作   │  正解 / お手つき │
  └──────────┘            └──────────────┘          └──────────────┘
        └────────────── Socket.IO サーバー（状態を1か所で持つ）──────────────┘
```

## 画面

| パス | 誰が見るか | 役割 |
|---|---|---|
| `/` | 主催者・参加者 | 部屋を作るか、参加コードを入れて部屋に入る |
| `/join/<参加コード>` | 参加者 | スマホで名前を登録し、早押しボタンを押す |
| `/screen/<主催キー>` | 会場全員 | プロジェクター投影用。QR・参加コード・問題番号・回答者名・正解発表。**表示専用**。管理画面の「投影画面を開く」から出せる |
| `/host/<主催キー>` | 司会・出題者 | 手元PCで進行を操作する。ここだけが状態を変えられ、YouTubeモードの曲もここで鳴る |

## 部屋

**主催者ごとに独立した「部屋」を作ります。** 早押し・参加者・お手つき・進行状態・曲リストは部屋の中だけで完結し、別の部屋には一切伝わりません。サーバーは1プロセスのままなので、早押しの排他判定は今までどおり確実です。

`/` で「新しい部屋を作る」を押すと、2つの値が発行されます。

| | 長さ | 誰に渡すか |
|---|---|---|
| **参加コード** | 4文字（`ABCD` のような形） | 参加者。QRとURLに載り、口頭でも読み上げられる。紛らわしい `I O 0 1` は使いません |
| **主催キー** | 16文字 | **誰にも渡さない。** 投影画面と管理画面のURLに入っていて、これを持つ画面にだけ曲データ（＝答え）が届きます |

ログインはありません。**部屋に戻るための資格は管理画面のURLだけ**なので、作ったら控えてください（管理画面の「管理URLをコピー」から取れます）。無くした場合は部屋を作り直します。

参加者に渡すのは `/join/<参加コード>` だけです。参加コードを知っているだけでは曲データは受け取れません（`scripts/roomtest.mjs` と `scripts/leaktest.mjs` で検証しています）。

**部屋はサーバーのメモリにしか無く、誰も繋いでいない状態が2時間続くと片付けられます。** サーバーを再起動したときも全部消えます。存在しない部屋のURLを開くと「部屋が見つかりません」と出ます。

## 出題者から見てできること

**早押し**

- 最初に押した1人だけが受理される。判定はサーバー側の単一プロセスで行うので、同時押しでも二重に通らない
- 押した瞬間、投影画面で効果音が鳴り、投影画面と管理画面の両方に回答者名が大きく出る（**参加者の端末では鳴らない**。音は会場に1つで足りる）
- 「押し直し」でロックせずに受付へ戻せる（誤検知・押し間違いの救済）

**お手つき**

- 「× お手つき」を押すと、その参加者はその問題だけロックされ、全画面に `3 → 2 → 1 → GO!` のカウントダウンが出て受付が再開する
- ロックは端末に保存した `clientId` と表示名の両方で照合する。**スマホをリロードしても、名前を変えても、別ブラウザで入り直しても解除されない**
- 管理画面の参加者名をクリックすれば、司会の判断で個別に付け外しできる

**正解発表**

- 「正解は…」の溜めを入れてから、曲名を1文字ずつ浮かび上がらせる。溜めの秒数は管理画面から調整できる
- **溜めのあいだにサビへ向けた助走が鳴る。** 溜めの長さぶん手前から、**音量を上げながら**再生するので、答えが出る瞬間にちょうどサビの頭が来る。管理画面のチェックで切れば、従来どおり溜めは無音になり、答えが出てからサビへ飛ぶ
- 曲名・アーティストに加えて「◯◯さんの推し曲」を出せる。持ち寄り形式の出し物向け。**`owner` が空なら、その帯は表示されない**ので、持ち寄りでない曲を混ぜてもよい

**出題データ**

- 曲リストは管理画面から直接編集できる。**JSONで書き出し・読み込みができる**ので、別のPCへ持ち込んだり、次回に使い回したりできる
- **YouTubeのURLを貼るだけで、動画ID・曲名・アーティストが入る。** `t=` 付きのURL（YouTubeの「共有 → 現在の時間から」）を貼れば、サビの開始秒も一緒に取り込む
- 曲名とアーティストは oEmbed から起こした**下書き**。「乃木坂46 『帰り道は遠回りしたくなる』」のような動画タイトルを、アーティストと曲名に割って入れる。アートトラック（「〇〇 - Topic」）にも対応している

**答えが漏れない**

- 曲名・アーティスト・推した人は、投影画面と管理画面にしか配信していない。参加者の端末には空で配られる
- 通信を覗いても答えが分からないことは、`scripts/leaktest.mjs` で検証している

## 自分で動かす

上のURLは動作を見てもらうためのものです。**本番で使うなら自分の環境に置いてください**（メモリ上の状態を他人と共有することになるのと、無料プランはスリープするためです）。

Node.js 20以降が必要です。

```bash
git clone https://github.com/<あなた>/intro-quiz.git
cd intro-quiz
npm install
cp public/songs.sample.json public/songs.json   # 曲データを用意する
```

開発時は、ターミナルを2枚開いて両方をリポジトリのルートで実行します。

```bash
npm run server   # Socket.IO・HTTPサーバー（ポート3000）
npm run dev      # Vite開発サーバー（通常はポート5173）
```

`http://localhost:5173/` を開いて「新しい部屋を作る」を押すと管理画面へ移ります。投影画面は管理画面の「投影画面を開く」から、参加者用URLは同じく「参加URLをコピー」から取れます。

スマホ実機から試すときは、PCとスマホを同じLANに繋ぎ、Viteが表示する Network URL（例 `http://192.168.1.20:5173/`）を開いて参加コードを入れます。

本番相当で確認する場合はビルドしてから単一のサーバーで配信します。

```bash
npm run build
npm start        # http://localhost:3000 で3画面すべてを配信
```

`npm run typecheck` で型チェックのみ実行できます。

### 環境変数

| 変数 | 既定 | 内容 |
|---|---|---|
| `PORT` | `3000` | サーバーの待ち受けポート |
| `PUBLIC_URL` | （`Host` ヘッダから組み立て） | 参加URLとQRに使う外向きのURL。リバースプロキシ配下で使う |
| `ROOM_TTL_MS` | `7200000`（2時間） | 誰も繋いでいない部屋を捨てるまでの時間 |
| `MAX_ROOMS` | `100` | 同時に持てる部屋の数。超えると部屋を作れない |
| `SWEEP_INTERVAL_MS` | `60000` | 部屋の掃除を回す間隔。検証用 |

## デプロイする

上のデモは Render の Web Service に置いてあります。同じ手順で自分の環境へ置けます。

| 項目 | 値 |
|---|---|
| Build Command | `npm install && npm run build` |
| Start Command | `npx tsx server/index.ts` |
| インスタンス数 | **1（絶対に増やさない）** |
| 環境変数 `PUBLIC_URL` | デプロイ後のURL（例 `https://your-app.onrender.com`） |

**インスタンスを増やすと壊れます。** 早押しの排他判定も部屋の状態もプロセスのメモリにあるので、2つに分かれると別々の部屋を持ってしまいます。

`PUBLIC_URL` は参加用URLとQRコードに使います。未設定でも `Host` ヘッダから組み立てますが、リバースプロキシ配下では取り違えることがあるので設定しておくのが確実です。

Vercel と Cloud Run は避けてください。前者は WebSocket の常時接続を維持できず、後者はインスタンスが勝手に増えます。

**無料プランは15分アクセスが無いとスリープし、復帰に30秒〜1分かかります。** 出番の20分前に一度開いて起こしておいてください。

`public/songs.json` はリポジトリに含まれないので、デプロイ先には**サンプルの3曲**が載ります。本番の曲は管理画面の「曲を編集」から入れ、「JSONとして書き出す」で控えておいてください。

## 曲データを用意する

`public/songs.sample.json` をコピーして `public/songs.json` を作ります。**`public/songs.json` は `.gitignore` 済みです**（参加者の実名が入るため、コミットされない運用にしています）。

`songs.sample.json` にはデモ用の3曲が入っています。`songs.json` を作らずに起動すると、この3曲で動きます。まず動かして雰囲気を掴んでから、自分の曲に差し替えてください。

```json
[
  {
    "videoId": "dQw4w9WgXcQ",
    "title": "曲名",
    "artist": "アーティスト名",
    "owner": "曲を推した人の名前",
    "startSec": 0,
    "chorusSec": 43
  }
]
```

| 項目 | 内容 |
|---|---|
| `videoId` | YouTube URLの `v=` より後ろにある動画ID |
| `title` | 答えとして投影する曲名 |
| `artist` | 答えとして投影するアーティスト名 |
| `owner` | 曲を推した人の名前。画面に「さんの推し曲」が付く。**空にすればその帯ごと表示されない** |
| `startSec` | イントロ再生を開始する位置（秒） |
| `chorusSec` | サビの位置（秒）。正解時、「正解は…」の長さぶん手前から鳴り出し、答えが出る瞬間にここへ到達する |
| `volume` | この曲だけの音量（0〜100）。**省略すると全体音量に従う**（推奨）。管理画面のスライダーで調整・保存できる |

`songs.json` が無い場合は `songs.sample.json` にフォールバックするので、クローン直後でも起動はします。

### 曲リストはどこに残るか

**サーバーは曲を保存しません。** `songs.json`（無ければ `songs.sample.json`）は起動時に1度だけ読み込む**ひな形**で、部屋を作るたびにその複製が配られます。管理画面での編集はその部屋のメモリ上だけにあり、部屋が消えれば無くなります。DBを持たない方針のためです。そのぶん、残す手立てを2つ用意しています。

- **ブラウザに控える** — 「反映する」のたびに、その曲リストを管理画面の `localStorage` に保存します。サーバーが初期値に戻っていると、管理画面に「前回この端末で使った曲リストがあります」と出て、ワンクリックで戻せます
- **JSONで書き出す／読み込む** — 曲リストをテキストとして保存できます。別のPCから読み込めるので、事前に作ったリストを当日持ち込めます

手元で動かしている場合は、書き出したJSONを `public/songs.json` に貼れば、**これから作る部屋**の初期値を差し替えられます（サーバーの再起動が要ります。既にある部屋には影響しません）。**ホスティング先にデプロイしている場合は、`public/songs.json` はリポジトリに含まれないので、上の2つを使ってください。**

### 埋め込み可否を確認する

サーバーを起動して `/embedcheck.html` を開くと、`songs.json` の全曲について**埋め込み設定（oEmbed）と実際の再生可否（本物のプレイヤー）**を一覧で確認できます。映像も出るので、`startSec` と `chorusSec` の位置合わせも同時にできます。

```
http://localhost:3000/embedcheck.html        # ローカルで動かしている場合
https://intro-quiz-u3vn.onrender.com/embedcheck.html   # デプロイ先の場合
```

**本番で使うChromeプロファイルで開いてください。** 「プレイヤー」欄の結果はログイン中のGoogleアカウントで変わります。

**この確認ページは、本番で使うChromeプロファイルで開いてください。** 「プレイヤー」欄の結果はログイン中のGoogleアカウントで変わります。

なお `https://www.youtube.com/embed/<videoId>` をアドレスバーに直接貼る確認方法は、**現在は使えません**。YouTube は2025年末から埋め込みプレーヤーが HTTP Referer で自分を名乗ることを必須にしたため、アドレスバーから開くと referrer が付かず、埋め込み可能な動画でも必ずエラー153になります。この確認ページは本物のページとして読み込まれるので referrer が付き、正しく判定できます。

## 再生モード

管理画面の右上で切り替えます。**既定は「YouTube」**です。手動モードは逃げ道として残しています。

### 手動モード（既定）

曲の再生を、司会が別ウィンドウのYouTubeで行うモードです。管理画面の「▶ イントロ」「♪ サビ」ボタンが、`t=` 付きURLで**同じ名前の再生タブを使い回して**頭出しします。2回目以降はタブが切り替わらず、管理画面からフォーカスが外れません。正解を押したときにサビを自動で鳴らすこともできます（待ち時間は秒単位で調整可能）。

**問題を移ると、再生タブは自動で無音になります。** 正解発表で流したサビを手で止める必要はありません。別オリジンのタブは中身を触れませんが `location` への書き込みだけは許されているので、`about:blank` へ飛ばすことで音を止めています。タブ自体は閉じないので、次の曲でもフォーカスを奪わずに使い回せます。

早押しでの停止だけは手で行います。停止自体は同じ手が使えますが、再開に動画の読み込み直しが要るため、現状は入れていません。ビープが停止の合図になります。

### YouTubeモード

**管理画面に埋め込まれたプレイヤー**が曲を鳴らします。「▶ イントロ再生」「⏸ 一時停止」で操作でき、**早押しで自動停止**、**正解で `chorusSec` へ自動ジャンプ**、**お手つきの `GO!` で止めた位置から自動再開**します。準備が終わるまで再生ボタンは押せません。

**音量は2段構えです。** まず「全体音量」（既定70）で会場に合わせ、**目立つ曲だけ**「この曲」のスライダーで上書きします。曲ごとの設定を持たない曲はすべて全体音量で鳴るので、1曲ずつ触る必要はありません。上書きした曲は「全体に戻す」で元に戻せます。

曲ごとの調整が要るのは、YouTube のラウドネス正規化が[大きい音を下げるだけで、小さい音を持ち上げないため](https://www.criticallisteninglab.com/en/learn/loudness/youtube)です。商用マスターそのものであるアートトラック（「〇〇 - Topic」）は -14 LUFS まで下げられて揃いますが、それより静かなMVはそのままなので、混ぜると音量差が残ります。

プレイヤーを管理画面の中に置いているのは、[Chrome が「隠れている画面で開始された再生」を前面に来るまで延期する](https://www.chromium.org/audio-video/autoplay/)ためです。これは自動再生の許可の問題ではないので、事前のクリックでは回避できません。**再生ボタンを押す瞬間、管理画面は必ず前面にあります。** だからここに置けば、延期される条件が原理的に成立しません。投影画面や別ウィンドウに分けると、その画面を常に見える位置に置き続ける必要が出てしまいます。

### なぜ手動が既定なのか

YouTube埋め込みは、動画ごとに埋め込み再生が禁止されている（エラー101 / 150）、広告が入る、回線状況でイントロの頭が欠ける、といった当日に対処できない失敗をします。手動モードはそのすべてを人力で回避でき、早押し・ビープ・回答者表示・正解演出は手動モードでも完全に動きます。**本番前に全曲をYouTubeモードで通しで試して、1曲でも不安があれば手動で通す**という判断ができるように、2モードを用意しています。

なお、IFrame Playerを非表示にして音声だけ使う運用はYouTubeの利用規約上グレーです。継続的に使うなら手動モード、または自前の音源を検討してください。

## 設計の考え方

10分間の出し物を確実に成立させることを最優先に、意図的に機能を削っています。

**状態はサーバープロセスのメモリだけに持つ。** DBもRedisも使いません。再起動すれば参加者も進行状態も消えますが、10分の出し物ではその方が壊れる箇所が少なくなります。逆に、**早押しの排他制御が単一プロセス前提なので、本番サーバーを複数インスタンスに増やすと破綻します**。

**認証を持たない。** 参加者がログインする体験は、10分の出し物では成立しません。`/host` にも認証がないので、**公開URLで運用する場合は当日以外はデプロイを落としてください**。

**楽曲の音声ファイルは持たない。** 曲は YouTube から再生するので、リポジトリに mp3 を抱えません。早押しの効果音だけは [public/sfx/](public/sfx/) に置いています（[効果音ラボ](https://soundeffect-lab.info/)。商用無料・クレジット表記任意で、この使い方が再配布に当たらないことを配布元が明示しています）。**音源の読み込みに失敗しても無音にはなりません。** Web Audio で組み立てた合成音（[src/beep.ts](src/beep.ts)）へ落ちます。管理画面の「試聴」で、参加者に押してもらわずに音を確認できます。ブラウザの自動再生制限に対しては、`/screen` の「投影を開始する」と `/host` の「操作をはじめる」の1クリックで解除する形にしています。

**参加者の識別は `localStorage` の `clientId`。** スマホがリロードしても、電波が切れて繋ぎ直しても、同じ人として復帰します。お手つきロックが「リロードで消える」のは出し物として致命的なので、ここだけは丁寧に作っています。

**投影画面は完全に表示専用。** `/screen` はサーバーの状態をそのまま描くだけで、キー操作も受け付けず、曲も鳴らしません。操作口を `/host` の1か所に絞ることで、当日「どっちの画面で操作するんだっけ」が起きないようにしています。YouTubeのプレイヤーを投影画面ではなく管理画面に置いているのも同じ考えで、**いちばん壊れてほしくない画面から、いちばん壊れやすい部品を外す**ためです。

## 既知の制約

- 早押しの排他は単一プロセス前提。水平スケールできない。部屋を増やしてもプロセスは1つのまま
- サーバー再起動で部屋・参加者・進行状態がすべて消える
- **認証はない。** 管理画面を守っているのはURLに入った主催キーの推測しにくさだけで、URLが漏れれば誰でも操作できる。人に見られる場所で管理画面のURLを開かないこと
- 部屋を作るのに制限がない。公開サーバーで運用するなら `MAX_ROOMS` を絞る
- 手動モードでは、早押しでの停止だけは人の手で行う必要がある（問題を移ったときの停止は自動）
- YouTubeモードでは、埋め込み再生が禁止されている動画は鳴らない（手動モードへ切り替える）
- YouTubeモードは、動画側の埋め込み設定・広告・回線に依存する
- **YouTubeモードの再生可否は、管理画面を開いたブラウザのGoogleアカウントで変わる。** Music Premium 限定の曲は、Premium のアカウントでないと鳴らない。事前チェックを別プロファイルで通すと本番で気づく
- 見出しの書体を Google Fonts から読むので、オフラインのLANだけで動かすとフォールバックの書体になる

## 検証スクリプト

`scripts/` に、実際にSocket.IOで繋いで振る舞いを検証するスクリプトを置いています。引数を省略すると `http://localhost:3000` に接続します。

| スクリプト | 検証内容 |
|---|---|
| `buzztest.mjs` | 同時押しで1人だけ受理、お手つきロック、3秒後の受付再開、押し直し、未登録の拒否 |
| `roomtest.mjs` | 別々の部屋が干渉しないこと。早押し・参加者・お手つき・進行状態・曲リストが混ざらず、参加コードでは答えを受け取れないこと |
| `hosttest.mjs` | 管理画面の操作が投影状態へ反映されるか、後から繋いだ画面への状態同期 |
| `relocktest.mjs` | 切断・再接続・名前変更をしてもお手つきが解除されないこと |
| `leaktest.mjs` | 参加者に答え（曲名・アーティスト・推した人）が配信されていないこと。役割を名乗っても受け取れないこと |
| `cleartest.mjs` | 「参加者を全員クリア」で、離脱者だけが消えて接続中の人は戻ること |
| `songstest.mjs` | 管理画面からの曲リスト編集が各画面へ配られること、曲ごとの音量が保存され範囲外の値が丸められること |
| `resumetest.mjs` | お手つきのカウントダウン後に曲が再開すること、鳴っていなかった曲は再開しないこと、演出を打ち切ったら再開しないこと |
| `sweeptest.mjs` | 誰も居なくなった部屋が片付けられること、人が居るあいだは残ること（**引数を取らず、寿命を短くした検証用サーバーを自分で起動します**） |
| `urltest.mjs` | YouTube URLからの動画ID・開始秒の抽出（サーバー不要） |
| `routetest.ts` | URLから部屋と立場（参加者・投影・管理）を読む処理（サーバー不要。`npx tsx` で実行） |
| `fittest.ts` | 投影画面の大きな文字を枠に収める計算。曲名の割れ方とはみ出しを防ぐ（サーバー不要。`npx tsx` で実行） |
| `metatest.ts` | 動画タイトルからの曲名・アーティストの取り出し（サーバー不要。`npx tsx` で実行） |
| `importtest.ts` | 貼り付けたJSONの読み込みと、壊れた入力の弾き方（サーバー不要。`npx tsx` で実行） |
| `loadtest.mjs` | 同時接続を増やしたときの早押し応答時間の計測 |

```bash
npm start                              # 別ターミナルでサーバーを起動しておく
node scripts/buzztest.mjs
node scripts/roomtest.mjs
node scripts/loadtest.mjs http://localhost:3000 30
node scripts/sweeptest.mjs             # これだけサーバーを自分で立てる（引数なし）
npx tsx scripts/routetest.ts           # .ts は tsx で実行（実装を直接importするため）
```

**各スクリプトは実行のたびに自分専用の部屋を作ります。** ブラウザで別の部屋を開いたままでも影響しません（他の部屋の参加者は人数に入らないため）。

リモート環境に対して実行する場合は第1引数にURLを渡します。環境変数 `D` で各確認の待ち時間をミリ秒指定できます（遅い環境向け）。

```bash
D=1500 node scripts/hosttest.mjs https://<デプロイ先のホスト>
```

**これらのスクリプトは部屋を作り、参加者の追加・問題選択・モード変更を実際に行います。** 操作は自分の部屋の中だけで完結しますが、本番進行中のサーバーではCPUと部屋数を消費するので避けてください。

## 技術構成

React + TypeScript + Tailwind CSS（Vite） / Express + Socket.IO（tsx で直接実行）。ビルド済みフロントエンドは同じExpressサーバーから配信するので、本番は1プロセスで動きます。型定義 [src/types.ts](src/types.ts) はサーバーとクライアントで共有しています。

配色・角丸・書体は [tailwind.config.js](tailwind.config.js) に役割名で置いてあります（`gold` = 正解へ向かうもの、`win` = 早押しが通った、`miss` = 不正解）。色を変えたいときはここだけ触れば4画面に効きます。**早押しボタンに赤を使っていないのは、赤を不正解の色として通しているためです。**

見出しの書体は Google Fonts から読み込みます。**読み込めなくても日本語のフォールバックで動きますが、会場の回線が細いと本番中に字が入れ替わって見えます。** 開演前に一度全画面を開いて読ませておいてください。

ルーティングライブラリは入れていません。URLの読み取りは [src/room.ts](src/room.ts) に集約し、どの部屋の誰として繋ぐかはSocket.IOのハンドシェイク（`auth`）で1度だけ決めます。接続後に自己申告できる形にすると、参加URLを知っている人が名乗るだけで答えを覗けてしまうためです。

## ライセンスと注意

- 曲データ（`public/songs.json`）はリポジトリに含みません。楽曲の再生は各自の責任と権利範囲で行ってください
- YouTube IFrame Player の利用は YouTube の利用規約に従ってください
- `owner` に実名を入れる場合、公開リポジトリにコミットしないよう注意してください
